# 沉浸式阅读中的视频学习

[使用手册](README.md) · [相关指南](READING_EXTENSIONS.md)

打开“学习”下的**阅读**，将 YouTube 或 Bilibili 网址添加到收藏中，然后在导师旁边学习。视频使用与文档相同的阅读材料、文字记录、注释和对话存储。媒体阶段支持转录搜索和关注、时间戳引用、全屏查看和当前/下一个字幕行。明确显示缺少的字幕或不支持的播放；导师不得声称仅观看了成绩单文本中的片段。

新的带时间戳的笔记是阅读注释。当编辑器打开时，会捕获它们的位置，因此在您书写时移动的播放不会移动注释。保存失败保留草稿以供重试；较旧的保存整理不会删除较新的文本。

## 现有观看对话

独立观看已停用。现有的 `/watching/{sessionId}` 和 `/learning/watching/{sessionId}` 链接打开了一条兼容性路线，将对话显式迁移到阅读中。对话 ID 和消息保持不变。旧版视频 JSON 保留提供者/缓存记录；现有的**视频学习**笔记本记录仍然可读且不会被重写。兼容的成绩单、笔记和保存的位置被幂等地复制到 Reading 中，并且现有的 Reading 位置胜过旧的导入位置。

会话列表和检查不会创建材料。当学习者打开旧对话或继续旧对话时，就会发生迁移。如果旧视频缓存丢失，其对话仍可作为普通聊天使用，并记录不可用视频状态；另一个视频永远不会默默地被替换。其他迁移失败会保留原始首选项并提供重试。

## 配置 Invidious

在管理员设置中，打开视频学习设置，输入实例的后端 API 源和公共源，测试连接，然后选择 Invidious 作为默认提供商。 Reading 的 YouTube 字幕加载器使用该配置的提供程序。哔哩哔哩保持独立。不可用的字幕服务不会使本机可播放的视频无法使用，但丢失的文字记录是可见的，并且导师的证据仍然有限。

`invidious.api_base_url` 必须可由后端访问；  `invidious.public_base_url` 必须可由浏览器访问。私有 HTTP 源可以在现有配置实例策略下使用环回、LAN 或覆盖地址。公共实例需要 HTTPS。保留`video_learning.json`中的设置；项目 `.env` 文件将被忽略。

使用添加材料对话框中的 **浏览 Invidious** 来搜索或从帐户的订阅和播放列表中进行选择。帐户令牌仍然是所有者私有的。没有 `GET:feed`、 `GET:playlists` 和 `GET:playlists/*` 的旧代币需要重新连接；无需订阅或播放列表变更。 DeepTutor 从不要求 Invidious 密码。授权发生在配置的实例上，回调反馈返回到 Reading，而无需在重定向目标中放置令牌。断开连接失败会保留令牌以供重试。

## 验证与恢复

检查播放、搜索、转录搜索/关注、时间戳引用以及注释保存/编辑/重试。重新打开迁移的对话并确认其消息历史记录和源标识保持不变。还要检查缺少的字幕、不可用的提供商、狭窄的屏幕和所有者访问边界。在部署或回滚过程中保留现有的数据目录和所有者身份；不要仅仅为了撤消前端更改而使用备份覆盖较新的用户数据。
