# 运行时设计：激活、工作人员和模型历史记录

[手册](README.md) · [架构](ARCHITECTURE.md) · [活动](EVENTS_AND_PROGRESS.md)

此页面保留了早期设计笔记中已实施的决策。它描述了当前的边界；历史内存测量和单机测试计数并不是性能保证。

## 延迟激活

工具/功能目录使用导入轻描述符。注册检查不得急于导入未使用的提供程序、解析器或可选模块。注册表按需加载实现；模块选择和插件批准在激活时仍然有效。兼容性导出可以使用惰性包装器来保留现有的导入路径。

前端同样推迟了设置编辑器。更改加载时保留锚/导航激活和身份验证单次飞行行为。通过导入边界测试和前端路由预算进行验证，而不仅仅是热流程计时。源所有者：[注册表](../deeptutor/runtime/registry/)、[模块组件](../deeptutor/modules/) 和[设置](../web/features/settings/)。

## 短暂的解析工作者

即使在线程中运行，大量同步提取也可以在长期存在的 API 进程中保留本机库内存。 [isolated-worker border](../deeptutor/runtime/isolated_worker.py) 通过 [ `worker_process.py` ](../deeptutor/runtime/worker_process.py) 启动一个短暂的解释器，使用内部可导入的可调用和私有的临时输入/结果文件。

这是受信任的内部IPC。它的序列化Python对象不是用于不受信任的上传或网络输入的API。客户端无法选择任意可调用对象。子进程边界在退出时释放其内存，但其本身并不是不可信代码的操作系统安全沙箱。

超时和取消必须在返回之前终止并加入进程树。并发量以 `DEEPTUTOR_ISOLATED_WORKERS` 为界（默认为 2）；呼叫站点可以覆盖默认超时。保持 [worker 测试](../tests/runtime/test_isolated_worker.py) 涵盖特定于平台的清理和结果/错误恢复。解析器失败必须与空的成功提取区分开来。

## 私模历史

显示消息和提供者就绪模型历史记录有不同的用途。 [ `model_history.py` ](../deeptutor/services/session/model_history.py) 保留版本化的私有 `model_turn`，其中包含准备好的输入、快照、模型/工具消息、重播元数据和请求指纹。公共会话响应和导出对其进行编辑。没有有效模型元数据的旧行保留其显示历史记录回退。

共享循环将不断变化的运行时事实附加为命名快照，同时保持常规指令的稳定。替换一个快照会更改该部分；它不得将源材料重新解释为系统政策。工具可用性、工作空间路径和资源权限仍然来自其正常权限。

保留/压缩必须将模型轮次的工具调用和结果保持在一起。中断的工具会得到明确的不可用结果，而不是捏造的成功响应。路由更改删除了不兼容的私人提供商重放字段，同时保留了公共证据。更改必须保留存储的对话内容和帐户/工作空间隔离。

## 缓存证据

请求缓存诊断比较规范的请求指纹和未更改的前缀消息。他们不证明提供商提供了缓存的令牌。实际的提供商使用计数器是计费/缓存命中行为的证据；路线更改、驱逐、工具更改和压缩可能会使重用失效。

从[模型历史回归](../tests/services/session/test_model_history.py) 和[请求缓存测试](../tests/services/llm/test_request_cache.py) 开始。选择加入[提示缓存集成测试](../tests/integration/test_prompt_cache.py) 使用具有配置的真实提供程序的合成输入：

```bash
DEEPTUTOR_CACHE_E2E=1 python -m pytest tests/integration/test_prompt_cache.py -q
```

这可能会导致提供商使用。通过的合成缓存探测不是生产延迟或成本基准，并且特定于阶段的管道可能具有与共享聊天循环不同的历史契约。
