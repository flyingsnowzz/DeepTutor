# DeepTutor × WorkBuddy 能力测试优先级

日期：2026-11-03

## 验收原则

1. 必须实际调用 DeepTutor，不能用 WorkBuddy 宿主生成内容冒充集成成功。
2. 不只检查 `succeeded`，还要检查本领域产物是否完整、正确、与主题一致。
3. 占位、空输出、研究大纲、脚本文本、宿主替代产物均不能算能力验收通过。
4. 超时、缺依赖或模型失败必须明确呈现，不能静默降级成另一个成功故事。
5. 媒体类能力必须通过 `artifact_get` 下载并验证文件格式，而不是只看 JSON 元数据。

## 本轮关键修复

- MCP 大结果截断不再把 `data` 对象变成字符串：任务状态、错误、产物协议字段保留，研究正文优先于调用遥测。
- 快速研究使用单研究块、一次工具轮和 90 秒工具上限；附件知识库场景由 DeepTutor 强制执行 RAG，模型不能跳过证据后直接 FINISH。
- 视频课在 MCP 中默认使用 `generation_mode=storyboard`：模型负责教学分镜，DeepTutor 负责受控 TSX、Remotion 校验和 TTS；HTML 不直接作为活动内容产物开放，而是打包成 ZIP。
- 数学动画初始代码生成使用低推理强度，避免 spark 模型把输出预算消耗在内部思考上。
- 研究报告写作步骤在快速模式有单步 90 秒预算；超时后使用真实研究证据生成明确标记的简版报告。

## 第二优先级：WorkBuddy 端到端复验

- 在 WorkBuddy 中重新验证深度研究：必须显示 DeepTutor 报告和知识库引用，而不是宿主自行搜索/写作。
- 在 WorkBuddy 中重新验证视频课 ZIP 下载和本地打开效果。
- 在 WorkBuddy 中重新验证数学动画 MP4 下载与播放。
- 分步解题：DeepTutor 返回完整求解步骤，而不是宿主讲解。
- 主观题判分：错误答案得到具体错因和形成性反馈。
- 资料精读：基于 PDF 回答并带页码/章节引用。
- 掌握路径：生成后可通过 `mastery_map_get` 读取阶段目标。
- 练习闭环：出题 → 入库 → 作答 → 判分 → 错题 → SRS 复习。

## 第三优先级：上线稳定性

- 长任务取消、超时和失败提示；
- `ask_user` 追问与继续执行；
- 幂等、额度与防重复扣费；
- HTTP 多账户隔离与 401 登录引导；
- 弱网或模型失败时禁止宿主静默代做。
