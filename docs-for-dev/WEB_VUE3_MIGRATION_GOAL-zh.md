# Codex 开发目标：将 `web` 完整迁移为 `web-vue3`

## 目标

把现有 `web/` 的 Next.js/React 前端完整迁移到独立的 `web-vue3/`，最终交付纯 Vue 3 前端。迁移期间维持现有 React 前端可用；Vue 版不得通过嵌入 React 页面或运行 React 组件来冒充已迁移功能。全部验收通过后，才修改默认启动、构建和部署入口。

## 范围与约束

- 覆盖 `web/app/**/page.tsx` 中的全部页面，以及页面实际使用的弹窗、侧栏、工作流、状态管理、快捷操作和错误处理。当前基线为 65 条页面路由，清单见 [`web-vue3/route-coverage.json`](../web-vue3/route-coverage.json)。
- 普通用户与管理员保持独立登录入口、账号和权限；用户可注册登录，超级管理员由部署配置指定，其他管理员由超级管理员创建。
- 沿用 DeepTutor 的 FastAPI、WebSocket 和 PostgreSQL 后端协议；迁移不改变现有数据归属和权限边界。
- 包括聊天流式事件与断线恢复、知识库、学习路径、阅读与视频、收藏夹、记忆、空间、伙伴、设置、管理后台等所有现有功能。
- 保留中英文界面、响应式布局、键盘与无障碍操作，以及现有文件上传、下载和可视化交互。

## 执行顺序

1. 建立共享的 Vue 组件、API 客户端、鉴权和路由框架，逐页对照 React 页面和后端接口。
2. 先完成登录、管理员、聊天和常用工作区流程，再迁移学习、知识库、记忆、空间、设置及其余页面。
3. 每个页面按真实交互验收后，将清单状态从 `pending` 改为 `in_progress`，最后改为 `complete`；仅能打开页面不算完成。
4. 对关键业务流程运行本地端到端验证，并检查普通用户与管理员权限隔离、WebSocket 恢复、上传下载和页面刷新。
5. 编写本地运行与云服务器部署文档。全部路由和关键交互达到功能等价后，切换默认前端入口并验证生产构建。

## 完成标准

- `route-coverage.json` 中 65 条原有路由均为 `complete`，新增的 React 页面也被纳入清单并完成迁移。
- `web-vue3/` 的运行时代码不依赖 React、React DOM、Next.js，且不转发到原 React 页面。
- 用户、管理员和超级管理员的核心操作在本地 PostgreSQL 环境中通过浏览器验证；关键流程与 React 版行为一致。
- `npm ci`、类型检查、生产构建和必要的端到端检查通过；前端启动和部署文档可复现。
- 默认启动入口切至 Vue 版后，现有功能无回退；仅在此时才考虑退役 `web/`。
