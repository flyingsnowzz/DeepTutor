# DeepTutor 项目架构与代码导读

> 适用版本：当前 1.7.0 源码布局  
> 整理日期：2026-11-03  
> 文档性质：当前实现导读，不是未来规划。  
> 推荐阅读对象：第一次接触本仓库，希望理解前后端、接口、TurnEngine、Agent、账号与数据存储的开发者。

## 1. 先用一句话理解项目

DeepTutor 是一个**前后端分离、Agent 原生的学习应用**：

- `web/` 是 Next.js 前端，负责页面、交互和流式结果展示。
- `deeptutor/` 是 Python 后端主体，负责接口、持久化、Turn 编排、Agent、模型、工具、账号、权限和数据。
- CLI、WebSocket 和 Python SDK 是三种使用入口，但最终都进入同一个 `TurnApplicationService`，避免各写一套对话逻辑。
- 一次用户请求被称为一个 **Turn**；Turn 由某种 **Capability** 接管，Capability 可以调用模型和多个 **Tool**。
- 执行过程通过统一的 **StreamEvent** 持续输出，并由运行时保存和重放。

最核心的调用链是：

```text
CLI / WebSocket / Python SDK
              │
              ▼
   TurnApplicationService
   持久化、提交、订阅、取消、恢复
              │
              ▼
         TurnEngine
              │
              ▼
      ChatOrchestrator
   根据 UnifiedContext 选择 Capability
              │
              ▼
          Capability
   单 Agent Loop 或多阶段 Pipeline
              │
              ▼
      Agent / LLM / Tools
              │
              ▼
         StreamEvent
   保存事件，并由入口适配器重放给消费者
```

## 3. 前后端是否分离，进程怎样运行

是前后端分离的。常规源码启动会得到两个主要进程：

| 进程 | 技术 | 默认地址 | 源码 |
| --- | --- | --- | --- |
| 前端 | Next.js、React、TypeScript | `http://localhost:3782` | `web/` |
| 后端 | Python、FastAPI、Uvicorn | `http://127.0.0.1:8001` | `deeptutor/` |

启动入口：

```bash
.venv/bin/deeptutor start --detach --no-browser
```

启动器位于：

- `deeptutor/runtime/launcher.py`
- `deeptutor_cli/main.py`

启动器负责：

- 找到可用端口。
- 启动后端 Uvicorn。
- 启动前端 Next.js。
- 等待两端 HTTP 就绪。
- 输出访问地址和日志位置。
- 管理停止、后台运行和进程生命周期。

常用验证地址：

```text
前端：http://localhost:3782/
聊天：http://localhost:3782/chat
后端就绪：http://127.0.0.1:8001/health/ready
```

### 3.1 浏览器是否直接请求 8001

通常优先把 `web/proxy.ts` 理解为前后端之间的服务侧代理：

```text
浏览器
  │ 同源请求 /api/*、/ws
  ▼
Next.js / web/proxy.ts
  │ 服务侧转发
  ▼
FastAPI :8001
```

这样做可以集中处理：

- 后端地址。
- API 和 WebSocket 转发。
- 认证 Cookie。
- 部署时的内外网地址差异。
- 部分 Host、Origin 和安全边界。

不要把部署地址、后端密钥或管理员凭据硬编码进浏览器组件。

### 3.2 `deeptutor_web/` 是不是前端源码

不是主要前端源码。日常前端开发看 `web/`。`deeptutor_web/` 主要服务于 Python 包装和前端产物集成，不应替代 `web/app`、`web/features` 等源目录。

## 4. 同一个仓库里的几种不同入口

DeepTutor 不只有网页一种用法：

| 入口 | 代码位置 | 用途 |
| --- | --- | --- |
| Web REST | `deeptutor/api/routers/` | 页面数据、设置、账号、知识库等 HTTP 请求 |
| Web WebSocket | `deeptutor/api/routers/unified_ws.py` | 网页对话、流式事件、取消和续传 |
| CLI | `deeptutor_cli/` | 命令行运行能力、知识库、服务、模块等 |
| Python SDK | `deeptutor/app/facade.py` | 在 Python 代码中启动和订阅 Turn |
| MCP Server | `deeptutor/mcp_server/` | 给 WorkBuddy 等外部 MCP 宿主提供工具 |

其中，**主 Web、CLI 和 Python SDK 共享 Turn 应用服务**。MCP 是外部宿主适配层，不是主网页必须绕行的中间层，也不是第二套教学内核。

### 5.1 `data/` 与源码要分开理解

`data/` 包含本地运行后产生的：

- 用户设置。
- 会话数据库。
- 工作区。
- 知识库索引。
- 日志。
- 账号和授权数据。
- 用户凭据。

它不是一个应该随意批量改写的普通代码目录。测试和脚本应使用临时 runtime home，不能把真实用户数据当测试夹具。

## 6. 前端代码怎样组织

前端根目录是 `web/`，使用 Next.js App Router。

```text
web/
├── app/                 # 页面、布局、路由组
├── components/          # 可复用 UI 组件
├── features/            # 按业务拆分的 domain/store/transport/UI
├── shared/              # 更底层的共享 UI 和传输原语
├── contracts/           # 生成和解析 API / Turn 协议
├── context/             # React Context
├── hooks/               # 通用 React Hooks
├── lib/                 # 认证、请求、模型设置等客户端逻辑
├── i18n/、locales/      # 国际化
├── public/              # 静态资源
├── scripts/             # 构建、契约、检查脚本
├── tests/               # 前端测试
├── proxy.ts             # API / WebSocket 代理
└── package.json         # 前端脚本与依赖
```

### 6.1 `web/app/`：页面和 URL

例如：

| 文件 | 对应页面 |
| --- | --- |
| `web/app/(auth)/login/page.tsx` | `/login` |
| `web/app/(auth)/register/page.tsx` | `/register` |
| `web/app/(admin)/admin/users/page.tsx` | `/admin/users` |
| `web/app/(utility)/profile/page.tsx` | `/profile` |
| 聊天相关 `page.tsx` | `/chat` 及具体会话 URL |

括号目录如 `(auth)`、`(admin)` 是 Next.js **路由组**，主要用于组织布局，本身不出现在 URL 中。

页面负责组合，不应把所有网络请求、重连、持久化和业务规则都堆进 `page.tsx`。

### 6.2 `web/features/`：业务功能

当前主要 feature 包括：

```text
features/
├── capabilities/
├── chat/
├── calendar/
├── co-writer/
├── knowledge/
├── multi-user/
├── notes/
├── runtime-status/
├── settings/
├── tasks/
└── ui-layout/
```

以聊天为例，`web/features/chat/` 进一步拆分：

- 对话状态和展示。
- Turn command。
- 流式事件处理。
- WebSocket transport。
- 重连策略。
- command delivery。

修改聊天协议时，不要在某一个 React 组件里临时创建一套 WebSocket；应先找到 feature 中现有的 transport 和 store。

### 6.3 `web/contracts/`：前后端协议

```text
web/contracts/
├── generated/api.ts
├── generated/turn-protocol.ts
├── parse/turn-command.ts
├── parse/turn-event.ts
└── schema/
    ├── openapi.json
    └── turn-protocol.json
```

它用于减少以下问题：

- 前端猜后端字段。
- 流式事件类型不一致。
- 命令字段改了但解析器没改。
- OpenAPI 与页面类型漂移。

`generated/` 是生成产物，应按仓库脚本重新生成，不要只手改生成文件而不改来源。

### 6.4 前端依赖边界

`web/.dependency-cruiser.cjs` 定义了依赖规则，重点包括：

- 避免循环依赖。
- 不从其他模块导入路由 `page.tsx`。
- shared 底层代码不能反向依赖上层业务。
- feature 的 domain/store/transport 不应随意依赖渲染层。

可用检查：

```bash
cd web
npm run architecture:check
npm run contracts:check
npm run typecheck
```

## 7. 后端 `deeptutor/` 的完整分层

`deeptutor/` 不只是“接口文件夹”，而是整个 Python 后端主体。

```text
deeptutor/
├── api/                 # REST / WebSocket 接口层
├── app/                 # 应用服务、SDK facade、Turn 请求契约
├── runtime/             # TurnEngine、Orchestrator、Registry、StreamBus、启动器
├── capabilities/        # 接管一个 Turn 的能力实现
├── agents/              # Agent Loop、阶段 Pipeline、共享结果封装
├── tools/               # 模型可调用的单功能工具
├── services/            # 配置、会话、模型、账号、知识库等业务服务
├── multi_user/          # 本地多用户身份、角色、授权和路径隔离
├── core/                # UnifiedContext、StreamEvent、Tool/Capability 协议
├── modules/             # 官方模块目录、manifest 和生命周期
├── services/session/    # 会话与 Turn 持久化
├── knowledge/           # 知识库相关功能
├── learning/            # 学习领域逻辑
├── reading/             # 阅读相关功能
├── book/                # 书籍/教材相关功能
├── partners/            # Partner 相关功能
├── plugins/             # 第三方插件生命周期
├── mcp_server/          # 外部 MCP 宿主服务
├── i18n/                # 国际化
└── utils/               # 通用工具函数
```

### 7.1 各层不能混为一谈

| 层 | 主要回答的问题 |
| --- | --- |
| API | 请求怎么进来，参数是否合法，调用者是否有权限 |
| App | 这个 Turn 如何提交、持久化、订阅、取消和恢复 |
| Runtime | 如何构造执行上下文、选择能力、注册工具、分发事件 |
| Capability | 这一类任务完整应该怎样完成 |
| Agent | 模型如何思考、调用工具、观察和继续循环 |
| Tool | 某一个具体动作怎样执行 |
| Service | 会话、配置、知识库、账号等具体业务怎样实现 |
| Core | 各层共同遵守的数据结构和协议是什么 |

## 8. 接口层：`deeptutor/api/`

### 8.1 FastAPI 入口

`deeptutor/api/main.py` 负责：

- 创建 FastAPI `app`。
- 配置中间件和 CORS。
- 初始化用户目录和运行时设置。
- 挂载内置和模块路由。
- 提供健康检查等应用级端点。
- 处理部分全局异常和访问日志。

`deeptutor/api/module_routes.py` 负责按模块挂载路由。官方模块是否 installed、enabled、ready 是不同状态，不能只看源码文件是否存在。

### 8.2 REST API

主要路由都在：

```text
deeptutor/api/routers/
```

常见文件：

| 文件 | 职责示例 |
| --- | --- |
| `auth.py` | 登录、注册、用户、角色、头像、设备凭据 |
| `multi_user.py` | 授权、监护人、学习限制、管理员工具 |
| `settings.py` | 模型和系统设置 |
| `workspace.py` | 工作区 |
| `sessions.py` | 会话管理 |
| `knowledge.py` | 知识库 |
| `memory.py` | 记忆 |
| `notebook.py` | 笔记本/收藏等 |
| `practice.py` | 练习 |
| `mastery_path.py` | 掌握度学习路径 |
| `reading.py` | 阅读 |
| `capabilities.py` | 能力目录与契约 |
| `tools.py` | 工具目录和设置 |
| `modules.py` | 模块状态与管理 |
| `plugins.py` | 插件管理 |

一个典型路由通常做以下事情：

1. 用 Pydantic 模型校验请求。
2. 用 `Depends(require_auth)` 或 `Depends(require_admin)` 检查身份。
3. 解析当前用户和工作区。
4. 调用 app/service/domain 层。
5. 把结果或统一错误返回给前端。

路由里不应重新实现一套模型 Loop，也不应绕过应用服务直接启动 Capability。

常见实际端点示例：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /health/ready` | 后端就绪检查 |
| `GET /api/auth/status` | 当前认证状态和用户信息 |
| `POST /api/auth/login` | 登录并设置会话 Cookie |
| `POST /api/auth/logout` | 退出登录 |
| `POST /api/auth/register` | 当前首管理员注册入口；公开 C 端注册需另行改造 |
| `GET /api/auth/users` | 管理员查询用户 |
| `POST /api/auth/users` | 管理员创建用户 |

router 文件中的装饰器可能只写 `/login`，完整路径还包含挂载时的 `/api/auth` 前缀；排查接口时应同时看 router 和挂载处。

### 8.3 WebSocket API

统一入口：

```text
deeptutor/api/routers/unified_ws.py
```

路由：

```text
/ws
```

它负责：

- 接收提交、取消、用户补充输入等命令。
- 调用 `TurnApplicationService`。
- 把 Turn 事件推送给浏览器。
- 支持断线后按序号继续订阅。
- 处理 session/turn 级协议。

REST 更适合普通资源操作；WebSocket 更适合持续对话事件。两者不是两套业务后端。

## 9. 一次网页对话的完整流程

下面以用户发送“解释傅里叶变换”为例。

### 第 1 步：前端提交命令

聊天页面通过 `web/features/chat/` 的 transport 发送命令，命令包含例如：

- 用户文本。
- session ID。
- client submission ID。
- capability/mode。
- 工作区信息。
- 必要的能力和模型配置。

前端协议解析位于 `web/contracts/parse/`。

### 第 2 步：WebSocket 适配器接收

`deeptutor/api/routers/unified_ws.py`：

- 校验消息类型和字段。
- 获取应用容器。
- 调用 `TurnApplicationService`，而不是自己创建 Agent。

应用容器位于 `deeptutor/app/container.py`，请求契约位于 `deeptutor/app/contracts.py`。

### 第 3 步：应用服务持久化并接纳 Turn

`deeptutor/app/service.py` 的 `TurnApplicationService` 负责：

- 解析并规范化 `TurnRequest`。
- 进入正确的账号/工作区写入范围。
- 创建或复用 session。
- 保存用户消息和 Turn。
- 处理 submission identity，减少重复提交。
- 创建运行时执行。
- 返回 session 和 turn 信息。

它的主要公开方法包括：

| 方法 | 用途 |
| --- | --- |
| `start_turn()` | 提交并启动 Turn |
| `subscribe_turn()` | 订阅单个 Turn 的事件 |
| `subscribe_session()` | 订阅 session 活动 |
| `cancel_turn()` | 请求取消 |
| `cancel_turn_and_wait()` | 等待取消完成 |
| `submit_user_reply()` | 提交等待中的用户回复 |
| `submit_user_input()` | 提交补充输入 |
| `regenerate_last_turn()` | 重新生成上一条回答 |
| `replace_submission()` | 编辑/替换原提交 |
| `list_sessions()` 等 | 会话管理 |

**这一层是持久化和生命周期边界，不是具体模型推理逻辑。**

### 第 4 步：TurnEngine 执行

`deeptutor/runtime/turn_engine.py` 是较薄的执行层。它把 `UnifiedContext` 交给 `ChatOrchestrator`，并输出 `StreamEvent`。

`deeptutor/app/engine.py` 只是兼容再导出，不是另一套 Engine。

### 第 5 步：ChatOrchestrator 选择 Capability

`deeptutor/runtime/orchestrator.py` 根据 `UnifiedContext`：

- 读取 `active_capability`。
- 默认选择 `chat`。
- 如果是 Partner/Connected Agent 代答，可能进入 handoff。
- 从 CapabilityRegistry 找到对应 Capability。
- 创建每轮 `StreamBus`。
- 调用 `capability.run(context, bus)`。
- 处理未知能力、失败、完成和用量等信息。

### 第 6 步：Capability 执行任务

例如：

- `chat` 走通用 Agent Loop。
- `deep_research` 走改写、拆解、研究、报告等阶段。
- `visualize` 走分析、生成、审查，或进入 Manim 子阶段。
- `video_lesson` 走代码生成、渲染检查和输出。

Capability 是“这次任务怎么完成”的负责人。

### 第 7 步：模型与工具执行

Agent Loop 可能：

1. 调用 LLM。
2. 收到工具调用请求。
3. 根据当前用户、工作区、能力和上下文判断工具是否可用。
4. 执行 Tool。
5. 把 ToolResult 返回给模型。
6. 继续循环，直到生成最终答案。

### 第 8 步：结果统一封装

所有能力最终汇聚到：

```text
deeptutor/agents/_shared/capability_result.py
```

统一结果包含：

- response payload。
- 用量和 `cost_summary`。
- 完成或失败所需的信息。

### 第 9 步：事件保存并推回前端

Capability/Agent/Tool 通过 `StreamBus` 发事件：

- 运行时持久化事件。
- 协调器发布新事件通知。
- `TurnApplicationService.subscribe_turn()` 按序号读取。
- WebSocket 适配器把事件发给前端。
- 前端解析并更新聊天界面。

断线重连后，不需要重新执行整个 Turn；可以按 `after_seq` 继续读取已保存事件。

## 10. Turn、Session、Submission、Event 分别是什么

| 概念 | 含义 |
| --- | --- |
| Session | 一段持续对话或学习会话，包含多条消息和多个 Turn |
| Turn | 一次用户提交到最终回答/失败的完整执行过程 |
| Submission | 客户端的一次提交身份，用于编辑、去重和持久化用户消息 |
| StreamEvent | Turn 执行中产生的阶段、内容、工具、结果或错误事件 |
| seq | 事件在 Turn 内的单调序号，用于持久化订阅和断线续传 |
| Capability | 接管 Turn 的任务能力 |
| Tool | Agent 在 Turn 内调用的一次具体工具动作 |

简化关系：

```text
Session
  └── Turn A
  │     ├── StreamEvent seq=1
  │     ├── StreamEvent seq=2
  │     └── StreamEvent seq=3
  └── Turn B
        ├── StreamEvent seq=1
        └── StreamEvent seq=2
```

## 11. Tool、Capability、Module 的区别

这是理解 DeepTutor 最关键的一组概念。当前有 **11 种用户可选择的 Capability**，详细配置与使用技巧见 `docs-for-dev/Capability功能与使用指南.md`。

### 11.1 Tool：一次单功能动作

Tool 通常由 LLM 按需选择，例如：

| Tool | 用途 |
| --- | --- |
| `brainstorm` | 头脑风暴 |
| `web_search` | 网页搜索与引用 |
| `paper_search` | arXiv 搜索 |
| `zotero_search` | Zotero 检索 |
| `reason` | 独立深度推理调用 |
| `geogebra_analysis` | 数学图片分析 |
| `imagegen` | 图片生成 |
| `videogen` | 视频生成 |

关键文件：

- `deeptutor/core/tool_protocol.py`：`BaseTool`、`ToolDefinition`。
- `deeptutor/tools/builtin/__init__.py`：内置工具包装与用户可切换白名单。
- `deeptutor/agents/_shared/tool_composition.py`：`ToolMountFlags` 和工具挂载规则。
- `deeptutor/runtime/registry/tool_registry.py`：工具注册。

并非所有内置工具都能由用户直接切换。`rag`、memory、notebook、`read_skill`、deferred MCP/CLI、`exec`、`ask_user` 等可能由上下文或 Capability 控制。

`--tool` 选择的是用户可切换白名单，不能绕过权限和上下文门槛。

### 11.2 Capability：接管完整 Turn

| Capability | 典型阶段 |
| --- | --- |
| `chat` | exploring → responding，默认通用 Loop |
| `ask_questions` | 通过 `ask_user` 的提问 Loop |
| `deep_solve` | 解题规划工具 + 解题 Loop |
| `deep_question` | ideation → generation |
| `deep_research` | rephrasing → decomposing → researching → reporting |
| `visualize` | analyzing → generating → reviewing，可进入 Manim |
| `math_animator` | 概念分析、设计、代码、重试、渲染输出 |
| `mastery_path` | 掌握度导航和 Guided Learning |
| `immersive_reading` | 文档或时间戳锚定的阅读 Loop |
| `video_lesson` | Remotion 代码、渲染检查、浏览器播放和 TTS |
| `audio_overview` | 检索、双人脚本、语音生成、音频与文字稿发布 |

关键文件：

- `deeptutor/core/capability_protocol.py`：`TurnCapability`、`CapabilityManifest`。
- `deeptutor/capabilities/`：具体实现。
- `deeptutor/runtime/registry/capability_registry.py`：注册。
- `deeptutor/runtime/bootstrap/builtin_capabilities.py`：从模块 manifest 形成内置声明视图。
- `deeptutor/capabilities/prompts/{en,zh}/`：能力提示词和状态文案。

### 11.3 Module：可独立包装的功能单元

Module 不只代表一个 Python 文件夹。manifest 可以声明：

- Python package paths。
- 依赖组。
- Capabilities。
- API routers。
- CLI groups。
- 前端 navigation。
- 生命周期回调。

manifest 位于：

```text
deeptutor/modules/manifests/*.json
```

例如：

```text
core.json
server.json
web.json
knowledge.json
research.json
visualize.json
video-lesson.json
```

要区分三个状态：

- **installed**：代码/包是否存在。
- **enabled**：是否被允许使用。
- **ready**：依赖和运行条件是否满足。

查看命令：

```bash
.venv/bin/deeptutor module list
.venv/bin/deeptutor plugin list
```

官方 Module 与第三方 Plugin 不是同一个概念，插件还有额外的审核和生命周期规则。

## 12. Runtime 目录为什么这么大

`deeptutor/runtime/` 不只是 TurnEngine：

| 位置 | 职责 |
| --- | --- |
| `turn_engine.py` | 执行 UnifiedContext 的薄入口 |
| `orchestrator.py` | 选择 Capability、管理执行和总线 |
| `stream_bus.py` | 每轮异步事件 fan-out |
| `registry/` | Tool 和 Capability 注册、scoped registry |
| `bootstrap/` | 内置声明和启动视图 |
| `coordination/` | Turn lease、事件 journal、通知、恢复；可有 memory/Redis 实现 |
| `launcher.py` | 前后端进程启动与停止 |
| `home.py` | runtime home 解析 |
| `agentic/` | 较低层 Agent 运行、消息、工具调用和用量 |
| `providers/` | 运行时 provider 视图和授权 |
| `ts_engine/` | TypeScript engine 实验/迁移路径 |
| `worker_process.py` 等 | 工作进程和隔离执行支持 |

修改事件、取消或恢复逻辑前，必须同时理解 app service、session store、coordination 和 stream bus，不能只看 orchestrator。

## 13. Services、Core 和其他后端目录

### 13.1 `deeptutor/services/`

这是业务服务最集中的地方：

| 目录 | 职责示例 |
| --- | --- |
| `config/` | JSON 设置、运行时覆盖和配置 schema |
| `session/` | Session、Message、Turn 和事件持久化 |
| `llm/` | LLM 客户端、指标和模型调用支持 |
| `workspace/` | 工作区上下文、迁移和资源绑定 |
| `accounts/` | 云端多账户/订阅服务 |
| `auth/` | 本地 Web 认证导出及云端 AuthService 子模块 |
| `postgres/` | PostgreSQL 连接支持，主要服务云端路径 |
| `quota/` | 配额、计数、幂等扣费 |
| `jobs/` | 长任务和 Artifact 服务 |
| `storage/` | 对象存储适配 |
| `rag/` | RAG 和检索流水线 |
| `memory/` | 记忆 |
| `notebook/` | 笔记相关服务 |
| `parsing/` | 文档解析 |
| `subagent/` | 本地/远程 Agent 连接器 |
| `sandbox/` | 代码执行隔离 |
| `skill/`、`mcp/` | Skills 与 MCP 配置服务 |

### 13.2 `deeptutor/core/`

这里放跨层共享协议：

- `context.py`：`UnifiedContext`。
- `stream.py`：`StreamEvent` 和 `StreamEventType`。
- `tool_protocol.py`：Tool 协议。
- `capability_protocol.py`：Capability 协议。

`StreamEventType` 包括：

```text
stage_start、stage_end
thinking、observation、content
tool_call、tool_result、progress
sources、result、error
session、session_meta、done、wait_for_input
```

一个事件带有：

- `type`
- `source`
- `stage`
- `content`
- `metadata`
- `session_id`
- `turn_id`
- `seq`
- `timestamp`

### 13.3 `deeptutor/agents/`

它更靠近“怎样让模型完成任务”：

- 通用 Agent Loop。
- 工具调用和观察。
- 多阶段 Pipeline。
- Capability 共享结果封装。
- 用量记录。
- 不同能力的提示词和阶段控制。

不要把所有业务都放进 runtime；具体解题、研究、阅读等流程通常属于 Capability/Agent。

## 14. 账号、工作区和数据隔离

### 14.1 账号和工作区是两个检查

通过认证只说明“你是谁”，并不自动说明“你能使用哪个工作区或资源”。

```text
认证：当前用户是谁？
  ↓
账号权限：是不是 admin？有哪些 grants？
  ↓
工作区：当前请求选择哪个 workspace？
  ↓
资源授权：该工作区能用哪些知识库、Skill、MCP、工具？
```

相关代码：

- `deeptutor/api/routers/auth.py`
- `deeptutor/multi_user/models.py`
- `deeptutor/multi_user/context.py`
- `deeptutor/multi_user/learning_access.py`
- `deeptutor/multi_user/*_access.py`
- `deeptutor/services/workspace/`

HTTP 可通过 `dt_workspace` 查询参数或 `X-DeepTutor-Workspace` 请求头选择工作区；WebSocket 建立时固定范围。前端 URL 中的 `dt_workspace=` 就与这个机制有关。

### 14.2 本地多用户目录

```text
data/user/                # 管理员默认工作区
data/users/<user-id>/     # 普通用户工作区
data/partners/<id>/       # Partner 合成用户工作区
data/system/              # 账号、授权、审计、索引和 owner secrets
```

路径决策主要在：

- `deeptutor/multi_user/paths.py`
- `deeptutor/services/path_service.py`
- `deeptutor/services/workspace/context.py`

`data/system/user-secrets/` 等 owner-private 内容不能暴露给 sandbox。

### 14.3 当前主 Web 账号特点

主 Web 已支持：

- 登录、退出和状态。
- 首管理员注册。
- 管理员创建、导入、删除用户。
- 角色、账号 preset、头像、学习者档案。
- 监护人与学习权限。
- 按用户隔离目录。

默认配置可能关闭认证，此时访问者按本地管理员使用。公网部署前必须检查 `auth.enabled`、HTTPS、Cookie、CORS 和代理边界。

C 端开放注册改造是另一项工程，不应把现有邀请制能力误认为完整 SaaS。专项计划见：

- `goals/C端Web账号体系改造计划.md`

## 15. 配置和本地数据存储

### 15.1 Runtime Home

`deeptutor/runtime/home.py` 解析 runtime home。默认通常是启动项目所在目录，也可通过：

- `DEEPTUTOR_HOME`
- `deeptutor start --home`
- `deeptutor init --home`

指定。

### 15.2 设置放在哪里

主要设置位于：

```text
data/user/settings/*.json
```

例如：

- `auth.json`
- `system.json`
- 模型和服务设置。

项目根目录 `.env` 不会被当作普通应用配置自动加载。部分进程环境变量有明确覆盖用途，容器启动也会进行 JSON 到环境变量的处理，但这不等于可以用根目录 `.env` 替代所有 JSON 设置。

配置实现：

- `deeptutor/services/config/runtime_settings.py`
- `deeptutor/services/config/settings_profile.py`

### 15.3 默认本地持久化

主应用默认可只用本地文件和 SQLite：

| 路径 | 内容 |
| --- | --- |
| `data/user/chat_history.db` | 会话、消息、Turn、练习等 |
| `data/user/.runtime/` | 私有运行时数据库 |
| `data/user/workspace/` | 默认 Content Workspace 和产物 |
| `data/knowledge_bases/` | 知识库索引和源数据 |
| `data/parse_cache/` | 文档解析缓存 |
| `data/user/logs/` | 日志 |

主 Web 的默认 SQLite/文件存储与云端 MCP 的 PostgreSQL 多账户路径要区分。设置一个 `DATABASE_URL` 不会自动把整个主应用迁移到 PostgreSQL。

### 15.4 备份注意事项

备份时应：

- 停止 DeepTutor 和 Partner 进程。
- 备份完整 runtime-home 的 `data/`。
- 如果 Content Workspace 在目录外，也要单独备份。
- 包含隐藏的 `.deeptutor/` 数据。
- 把备份当作敏感数据，因为可能包含对话、资料和凭据。

## 16. CLI 和 Python SDK 为什么不会绕过 Turn 逻辑

### 16.1 CLI

入口：

```text
deeptutor_cli/main.py
```

示例：

```bash
.venv/bin/deeptutor run chat "Explain Fourier transform"
.venv/bin/deeptutor run deep_solve "Solve x^2=4"
.venv/bin/deeptutor run visualize "Animate sine wave" --config render_mode=manim_video
.venv/bin/deeptutor chat
```

CLI 也进入应用服务，因此持久化、事件、取消和恢复语义与 Web 保持一致。

### 16.2 Python SDK

Facade 位于：

```text
deeptutor/app/facade.py
```

主要方法包括：

- `start_turn()`
- `stream_turn()`
- `cancel_turn()`
- `submit_user_reply()`
- `regenerate_last_turn()`
- `list_sessions()`、`get_session()` 等。

简化示例：

```python
from deeptutor.app import DeepTutorApp

app = DeepTutorApp(workspace_id="ws_...")
session, turn = await app.start_turn({
    "capability": "chat",
    "content": "解释傅里叶变换",
})

async for event in app.stream_turn(turn["id"]):
    print(event)
```

实际字段以 `deeptutor/app/contracts.py` 和当前 SDK 契约为准，不要在业务代码里绕过 SDK 直接实例化 Orchestrator。

## 17. MCP Server 与主 Web 的关系

`deeptutor/mcp_server/` 用于：

- stdio MCP。
- streamable HTTP MCP。
- 外部宿主身份和 Bearer token。
- 工具白名单。
- Job/Artifact。
- 配额和审计。

主 Web 不通过 MCP 调用自身：

```text
正确：
Web → TurnApplicationService → Capability

外部宿主：
WorkBuddy → MCP adapter → 同一应用/学习/Job 服务
```

MCP 层不应该重新实现第二套 Agent Loop，也不能向外部宿主暴露裸 `exec`、任意文件路径、provider 配置或系统管理工具。

## 18. 常见需求应该从哪里改

### 18.1 新增一个普通 REST 接口

建议顺序：

1. 在 `deeptutor/api/routers/` 找到所属 router。
2. 定义 Pydantic 请求/响应。
3. 加 `require_auth`、`require_admin` 或资源授权。
4. 在 `deeptutor/services/` 或领域模块实现业务。
5. 如果属于独立模块，在 `deeptutor/modules/manifests/` 声明 router。
6. 更新 OpenAPI/前端契约。
7. 在 `web/features/<domain>/` 增加 transport/store/UI。
8. 添加 API、权限和前端测试。

### 18.2 新增一种对话能力

主要看：

- `deeptutor/core/capability_protocol.py`
- `deeptutor/capabilities/`
- `deeptutor/modules/manifests/`
- `deeptutor/runtime/registry/`
- `deeptutor/agents/_shared/capability_result.py`
- `deeptutor/capabilities/prompts/{en,zh}/`

需要保证：

- CapabilityManifest 和 class path 正确。
- 输入 schema 明确。
- 最终走统一 result envelope。
- StreamEvent 和终态正确。
- 取消、失败和用量可观察。
- 模块依赖和前端 mode 可用。

### 18.3 新增一个模型工具

主要看：

- `deeptutor/core/tool_protocol.py`
- `deeptutor/tools/builtin/`
- `deeptutor/agents/_shared/tool_composition.py`
- `deeptutor/runtime/registry/tool_registry.py`

需要决定：

- 是否用户可切换。
- 是否只能某个 Capability 使用。
- 是否按知识库、账号或工作区上下文挂载。
- 参数、输出、错误和敏感权限如何约束。

不要只把名字加入白名单；白名单不等于挂载和授权规则。

### 18.4 修改聊天流式协议

需要同时检查：

- `deeptutor/core/stream.py`
- `deeptutor/runtime/stream_bus.py`
- `deeptutor/app/service.py`
- `deeptutor/services/session/`
- `deeptutor/runtime/coordination/`
- `deeptutor/api/routers/unified_ws.py`
- `web/contracts/schema/turn-protocol.json`
- `web/contracts/parse/`
- `web/features/chat/transport/`

必须验证：首次执行、断线重连、取消、完成、失败、等待输入和事件重放。

### 18.5 修改账号和权限

- 登录/注册/用户 HTTP：`deeptutor/api/routers/auth.py`
- 管理授权：`deeptutor/api/routers/multi_user.py`
- 用户模型：`deeptutor/multi_user/models.py`
- 当前用户：`deeptutor/multi_user/context.py`
- 身份存储：`deeptutor/multi_user/identity.py`
- 路径隔离：`deeptutor/multi_user/paths.py`
- 前端账号 API：`web/lib/auth.ts`、`web/features/multi-user/`
- 管理后台：`web/app/(admin)/admin/users/page.tsx`

主 Web 本地账号和 MCP 云端账号不是可以随意混用的同一套存储，改造前先读 C 端账号计划和相关架构文档。

### 18.6 新增或修改前端页面

- 页面和布局：`web/app/`
- 业务状态和请求：`web/features/`
- 通用组件：`web/components/`、`web/shared/`
- 认证：`web/lib/auth.ts`
- 协议：`web/contracts/`

优先复用 feature 内 transport/store，不要把 WebSocket、重试、账号判断和持久化散落在页面组件中。

### 18.7 修改模型或远程 Agent 接入

- 通用模型调用：`deeptutor/services/llm/`
- 模型设置：`deeptutor/services/config/`、`deeptutor/services/model_selection/`
- Subagent connector：`deeptutor/services/subagent/`
- connector 后端注册：`deeptutor/services/subagent/registry.py`
- connector 模型选项：`deeptutor/services/subagent/models.py`

模型 catalog、账号个人模型、管理员授权和运行时可用性不是一个层面的配置。

## 21. 最容易产生的误解

### 误解 1：`deeptutor/api/` 就是整个后端

不是。API 只是入口，Turn 持久化、Agent、模型、能力和数据服务都在其他目录。

### 误解 2：TurnEngine 包含所有 Agent 逻辑

不是。TurnEngine 较薄，Orchestrator 选择 Capability，Capability 和 Agent Loop 才负责具体任务。

### 误解 3：Tool 和 Capability 只是名字不同

不是。Tool 是单动作，Capability 接管完整 Turn；Capability 可以包含多个阶段和多个工具。

### 误解 4：网页聊天直接调用模型

正常路径不是。网页先进入应用服务，完成持久化和生命周期管理，再由 runtime 选择能力。

### 误解 5：主 Web 通过 MCP 调用自己

不是。主 Web 直接进入应用服务；MCP 用于外部宿主。

### 误解 6：认证通过就能访问所有工作区

不是。账号认证、工作区归属和资源授权是不同检查。

### 误解 7：所有数据都在一个数据库里

不是。默认本地布局同时有 SQLite、JSON、文件、索引和外部工作区；云端 MCP 另有 PostgreSQL 路径。

### 误解 8：源码里存在模块就一定可用

不是。installed、enabled、ready 必须分别检查。
